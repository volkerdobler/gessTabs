# Feature Roadmap — Editor Support Extensions

Forward-looking feature proposals (not code-quality cleanup, unlike P0–P3 above), derived from a research pass over `dokumentation/gesstabs_handbuch_52.md` (the ~19,000-line main handbook) and the ~15 topic-specific manuals in the same folder (Makros, CSV-Infile, InvertierteDateien, GESStabs-Artist, OfficeExport, Cellset, HTMLChart, Mehrebenenanalyse, Gewichten, SpaltenweiseSignifikanztests, Scoretab, Basiswechsel, Titlepage-Chapterpage, Totalcolumntable, Encoding). Goal: prioritize tooling that addresses complexity/pitfalls the manuals _themselves_ call out as error-prone, rather than generic "nice to have" editor features. Grouped into tiers (F0–F5) by dependency order and value; implemented roughly top to bottom, each item independently shippable. Line references below are to `dokumentation/gesstabs_handbuch_52.md` unless another file is named.

## F0 — Foundation: correct program-order / include-graph model

- [x] **Replace the flat "scan every `.tab`/`.inc` file in the workspace" model with an actual `INCLUDE`-graph resolver** ✅ Done (2026-08-26) — `src/includeGraph.ts` (`resolveIncludeGraph(entryFile, readFile, options)`), unit-tested in `test/includeGraph.spec.ts` (19 tests, no live vscode needed — same "pure function + injectable I/O" pattern as `matching.ts`/`fsutils.ts`). Given an entry file and a `(path) => string[] | undefined` reader, it walks `INCLUDE = <file>;` statements (quoted or bare, resolved relative to the _including_ file's directory, nesting supported) and tracks `#define`/`#undefine`/`#ifdef`/`#ifndef`/`#else`/`#end` state — including the OR-bracket form `#ifdef [ a b c ]`, AND-via-nesting, and the documented case-sensitivity quirk (`#define`/`#ifdef` names are case-sensitive unless `#ignorecase = yes;` is set, unlike the rest of the case-insensitive language) — to produce one flat, linearly-ordered list of only the _active_ source lines across the whole include tree, tagged with their original file+line. `INCLUDE`/`#define`/etc. text inside comments or strings is correctly ignored (reuses `Scope` via a minimal fake `vscode.TextDocument`, exactly like `test/scope.spec.ts`'s `makeDoc()` helper). Include cycles (direct or indirect) and a nesting-depth cap (default 20, mirroring the compiler's documented macro-nesting limit — there's no documented INCLUDE-specific limit) are both detected and reported as structured errors rather than hanging or crashing. On the "wrinkle" flagged when this item was written — appendix error `27: nested INCLUDE not allowed` (line 17220) vs. the main text's explicit "geschachtelte INCLUDEs" support (line 533-534) — nesting is implemented as supported, matching the main text and the multiple real nested-INCLUDE examples elsewhere in the handbook (e.g. `CSVINFILE = csv.csv; INCLUDE = var.inc;` patterns around line 16045-16151); the appendix entry is most likely a legacy or narrower-context restriction (not reproduced here) rather than a current hard rule, but flag this if a real script trips it. **Explicitly out of scope for this pass** (left as plain, unexpanded content — see the module's own doc comment): `#MACRO`/`#DOMACRO` expansion and `#EXPAND` substitution (that's F3's job, built on top of this); and evaluating `#IFEMPTY`/`#IFNEMPTY` (depends on `#EXPAND` values) or `#IFEXIST`/`#IFNEXIST` (depends on variable-definition tracking, itself a _consumer_ of this module) — both are conservatively treated as always-active (both branches kept) rather than guessed at, to favor false positives (an extra candidate definition) over false negatives (silently hiding a real one). `npm test` (60/60), `npm run compile`, `npm run lint` (0 errors) all verified.

## F1 — Core tooling: keyword knowledge base, hover, autocomplete, snippets ✅ Done (2026-08-27)

- [x] **Build a mechanically-extracted keyword database from the manuals.** ✅ `scripts/extractKeywordDatabase.ts` (run once via `npm run extract-keywords`, NOT part of compile/test/lint — `dokumentation/*.md` is git-ignored, so this only works with a local checkout that has the manuals) mines `dokumentation/*.md` into `src/keywordDatabase.ts`, a committed static data file (656 entries: 647 from the main handbook, 9 from topic-manual `Syntax:` blocks). Committing extracted text from git-ignored source manuals into tracked source was a deliberate call, confirmed with the user first. The original plan assumed the "Name/Beschreibung" two-column pattern was common and that `GESStabs_OfficeExport.md`/`GESStabs_GESStabs-Artist.md` had their own extractable glossaries — checked directly, and neither held up: the "Name Beschreibung" header only appears in one ~640-line CELLELEMENTS section, and the topic manuals turned out to be free-flowing how-to prose (`GESStabs_Makros.md` has zero ALL-CAPS heading-shaped lines or `Syntax:` anchors; `GESStabs_OfficeExport.md` has exactly one of each), not reference glossaries — mining them the same way would mean guessing at heading shapes in ordinary prose, so they're left as "Syntax:"-anchor-only sources and otherwise untouched ("prose to read", per the script's own header comment). Real bugs found and fixed along the way: (1) an initial `#END`/`END` name collision — two different, unrelated keywords (the preprocessor's block-closer vs. the script-terminator statement) were merged into one entry because the lookup key stripped a leading `#`; fixed by keeping `#`-prefixed and bare keys distinct (`keywordLookupKey`/`keywordLookupKeyAt` in `src/keywordDatabaseTypes.ts`, unit-tested) and reinstating the `#` at lookup time by checking the source character right before the word (vscode's own `wordPattern` never includes `#`); (2) the handbook's own end-of-book alphabetical INDEX (two PDF columns flattened into interleaved single-column "WORD pagerefs" lines with no blank-line separation) was silently producing garbage descriptions for real keywords like `MACRO`/`#ELSE` — now excluded entirely (`findAppendixIndexStart`, truncates at the index section's own repeating "Index <pagenum>" running header); (3) a standalone ALL-CAPS line inside an inline tutorial CODE EXAMPLE (e.g. `#ELSE` as one line of a `#IFDEF`/`#ELSE`/`#END` sample) looks identical in shape to a real glossary heading — fixed with a cheap, effective discriminator: real descriptions are German prose and reliably contain a common stopword (der/die/und/kann/mit/...), a code line never does (`looksLikeProse`); (4) the merge strategy started as "longest description wins" on a name collision, which backfired directly (a later, badly two-column-flattened occurrence of `FILTER` was _longer_, precisely because it had accidentally swallowed the _next_ entry's content too, and so won over the correct, clean, earlier one) — switched to first-valid-candidate-wins, matching "the primary definition is usually introduced first"; (5) a `Syntax:` block's first token isn't always its true subject (e.g. `TABLEFORMAT +/- AUTOSORTTREE;` is actually documenting the `AUTOSORTTREE` flag) and could run on into unrelated prose commentary — added `looksLikeSyntax` (a real grammar line reliably contains `< > = ; { } |`) to stop syntax-line accumulation the moment a line stops looking like grammar, and a length cap with sentence-boundary-aware truncation (`truncateDescription`, 400 chars) as a last-resort safety net for the cases with no clean heading boundary at all (confirmed on `FILTER`, whose real explanation runs straight into an unrelated `SORT` explanation with no line break of its own to detect). **Known, accepted limitations**, all confirmed directly rather than assumed: the source `.md` files already have every ä/ö/ü/ß replaced with "�" by an earlier, lossy conversion — unrecoverable, passed through as-is; inline PDF cross-reference page numbers embedded mid-sentence (e.g. "SORT 462") are left in; a small number of entries are still imperfect where the source's two-column-table flattening genuinely destroyed the per-item boundary (spot-checked via random sampling — the clear majority are clean).

## F2 — Diagnostics grounded in documented pitfalls ✅ Done (2026-08-27)

Each item below mirrors a failure mode the manual explicitly calls out (often with its own compiler-level mitigation flag) — these are not speculative lint rules, they're documented "this goes wrong in practice" patterns. Cross-referenced against the ~850 numbered compiler error codes in the appendix (`7.3 Liste aller Syntaxfehlermeldungen`, from line 17190) so diagnostic messages read like the real compiler's own errors.

All eight checks live in `src/diagnostics.ts` (pure, per-document, unit-tested — 38 tests in `test/diagnostics.spec.ts`) plus a thin wiring class, `GesstabsDiagnosticsManager` in `src/diagnosticsProvider.ts`. Unlike vscode's other provider interfaces there's no "DiagnosticProvider" registration point, so `extension.ts` wires it manually: a `vscode.DiagnosticCollection`, refreshed (300ms debounced) on `onDidOpenTextDocument`/`onDidChangeTextDocument`, cleared on `onDidCloseTextDocument`, and an initial pass over every already-open `.tab`/`.inc` document at activation. Gated behind one master switch, `gesstabs.diagnostics.enabled` (default `true`) — not eight individual toggles, to keep the settings surface from ballooning; can be split later if a specific check turns out too noisy in practice. **Deliberately scoped to the current document only**, like the document symbol/semantic-token providers — not the full resolved INCLUDE/#ifdef workspace `symbolIndex.ts` builds for go-to-definition/references. A duplicate declaration or `#define` reference across an INCLUDE boundary is consequently a known, accepted gap (see TODO.md) — resolving the whole workspace on every keystroke for eight independent checks was judged a bigger design (and performance) undertaking than this pass, and can build on the existing `buildWorkspaceIndex` machinery later if it proves worth it.

- [x] **"Empty varlist binds to last-created variable" trap.** `checkEmptyVarlist`. `VARTITLE`/`TITLE`/`VARTEXT`/`TEXT`/`VALUELABELS`/`LABELS` share a simple shape — their own syntax has an _optional, bracketed_ varlist (`VARTITLE [<VarList>] = "text";`), so "empty" is just the keyword directly followed by `=`. `RECODE` turned out structurally different and needed its own real syntax check (no optional-bracket varlist at all — confirmed against the handbook's own worked examples, ~line 6505-6511): its "empty" form is a _pure value list_ (`RECODE 1 2 3 = 3;`), whereas a real varlist form always has at least one non-numeric variable-name token before the first `=` (`RECODE item1 item2 1 = 4;`) — so the check is "does everything between RECODE and = consist only of digits/commas/colons/whitespace", not "is there nothing at all before =".

(3) Added `#EXPAND` hover: `findExpandDefinitions` parses `#EXPAND #name value` lines (name matched case-sensitively, like `#define`/`#ifdef` — unlike macro names) into a name→value map; hovering a bare `#name` that isn't a column-1 macro call now shows the defined value via the same `GesstabsMacroHoverProvider`. - [x] **Single-line `#ifnempty ... #else ... #end` (or any line carrying more than one preprocessor directive) was misread as an unclosed block** (2026-08-28). `checkUnmatchedBlocks` (F2), `findFoldRanges` and the formatter's indent pass each had their own `^\s*#...`-anchored regex copy that recognised at most one directive per line and `return`ed from the line the moment it matched one — so on `#ifnempty "&rows" &rows #else 1:99 #end` (a valid, common single-line idiom in macro bodies) the `#else`/`#end` after the `#ifnempty` were never seen: false "unclosed conditional block" error, everything after it over-indented, no fold. - [x] **Follow-up: the same one-directive-per-line assumption in `src/includeGraph.ts` was dropping later `#MACRO` definitions** (2026-08-28). New `test/includeGraph.spec.ts` cases (single-line `#ifnempty`, single-line `#ifdef`, two closers on a line, directive-in-string/comment). `npm test` 234/234, `npm run lint`/`tsc` clean. The corresponding TODO.md entry is removed.

- [x] **Macro hover no longer flattens nested macro calls** (2026-08-28). Reported from the field: hovering `#fillSlide10(…)` showed just a stray comment line and blank lines. Cause: the body is a series of nested calls — `#barchart(…)`, `#filltext(…)`, `#filltable(…)`, `#addlblsyintable(…)` — and those macros (like `#powerchart`) wrap their real content in `#ifdef PowerChart … #end`; with `PowerChart` not defined in the resolution, each resolves to an empty body, and the transitive expansion replaced every call with that empty body → the lines silently vanished.
